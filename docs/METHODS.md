# Methods

## Milestone 2 document handling

MIA stores the uploaded original unchanged at `storage/documents/<uuid>/original.<ext>`. It computes SHA-256 from the original bytes before extraction. Extracted text is a separate UTF-8 JSON sidecar containing raw page text and page references; it is never written back over the original. The word count is the number of whitespace-separated tokens after Unicode NFKC normalization. NFKC is used only for counting and duplicate comparison; raw extracted text remains separately preserved.

PDF pages are read with PyMuPDF in page order and text-block sorting. Ruled tables detected by PyMuPDF are reconstructed as tab-separated cell rows; pages with detected tables are flagged because merged cells and unusual layouts may be imperfect. When a page contains images and fewer than eight text words, MIA attempts PyMuPDF's Tesseract bridge at 200 DPI if the `tesseract` executable is available. OCR pages are flagged and must be checked against the original; OCR language defaults to English. If OCR is unavailable or yields no useful text, the upload is rejected with an explicit error. DOCX preserves body order, recursively reads nested tables, and includes distinct paragraph text from headers and footers; pagination depends on rendering and cannot reliably be recovered from the file. LaTeX `.tex` source has comments and common wrappers/macros removed while retaining ordinary prose, common math content, list items, and tabular cell text. This is a readable-text conversion, not a full TeX compiler; custom macros and deeply nested constructs may not be interpreted. HTML visible text is extracted with the standard-library HTML parser while script, style, template, and head contents are omitted. XML text nodes are read with ElementTree. Plain text, Markdown, CSV/TSV, JSON, YAML, TOML, RST, and similar formats use charset-normalizer; non-UTF-8 decoding is explicitly flagged. For short ambiguous Western-language samples, a Windows-1252 candidate is preferred only when it yields more common Latin diacritics than the top candidate, avoiding a tested mojibake case. Legacy DOC, ODT, and RTF use local LibreOffice command-line conversion with a 30-second limit and isolated profile; this parser is optional and reports an explicit error when LibreOffice is unavailable. Repeated nontrivial lines across PDF pages produce a possible header/footer warning. The multi-column warning uses text block x positions and is heuristic; reading order is not guaranteed for complex layouts.

The home page offers one upload-to-inference flow. It saves the original and extracted text, ensures the pinned RoBERTa model passes its real inference health check, then submits the saved document for prediction. A health-check or prediction failure remains visible; the saved document can be retried. MIA does not call commercial detector APIs. The detector is English-only and requires at least 50 whitespace-separated words.

Exact duplicates are rejected by original-file SHA-256 and include the existing document identity. Near duplicates use five-word shingles and Jaccard similarity; scores at or above 0.50 are recorded as flags. This intentionally simple screen is not a plagiarism decision and can miss paraphrases or flag common formulaic prose. It does not infer authorship.

Provenance and language background are declared in metadata. HUMAN records require source and a license or consent record. AI_GENERATED records require model, version, and prompt reference. AI_ASSISTED records require model, version, and editing history. Invalid declarations are rejected. Document create, metadata update, archive, and manifest import are recorded in audit events.

CSV manifest export records the document ID, filename, original hash, and metadata/storage manifest. Import validates the metadata and confines referenced file paths to the document storage root, checks the original's SHA-256, and checks the extraction sidecar before restoring missing rows. The manifest does not embed document contents.

## Milestone 3 detector inference

The `roberta-openai` adapter pins `openai-community/roberta-base-openai-detector` to revision `6cba99c003b711c7fe94f8a3aa2be35a792cb6fa`. It loads the model and fast tokenizer lazily, uses MPS when available and CPU otherwise, and retries on CPU if MPS inference fails. The start script sets `PYTORCH_ENABLE_MPS_FALLBACK=1`. Hugging Face files are cached under `MIA_MODEL_CACHE` (default `storage/models`) and are not committed.

The model's labels are `Fake` and `Real`. MIA reports the Fake-class softmax output as a model probability, not as a calibrated probability of AI authorship. Text shorter than 50 whitespace-separated words or whose declared language is not English is rejected. Longer texts are split into consecutive non-overlapping token windows within the 512-token sequence limit. The displayed score and final label use the unweighted mean of the per-window softmax probabilities; raw probabilities for each chunk are retained in the result JSON. Each prediction is persisted with the document's declared provenance, model revision, device, duration, configuration, and raw output. Failures persist an error result with no score; failures before an inference record can be created return a specific HTTP error.

Each single-document M3 inference creates a minimal technical experiment row to satisfy the result foreign key. It has no classification rule and produces no aggregate metrics or authorship conclusion. Milestone 5 adds frozen, multi-document experiment protocols separately.

## Milestone 4 winnowing similarity

`mia-detect.similarity` has no runtime dependency beyond Python's standard library. It applies Unicode NFKC, case folding, and word tokenization based on Unicode letters, combining marks, and numbers. Punctuation and whitespace separate tokens and do not enter a fingerprint. Token offsets point back to the original text so returned ranges can be highlighted without rewriting stored documents.

The default configuration uses `k=5` words per shingle and `w=4` consecutive shingle hashes per winnowing window. A full window selects its minimum 64-bit BLAKE2b hash; ties select the rightmost minimum. The threshold guarantee is `t = w + k - 1 = 8` words: any identical normalized run of at least eight words contains a selected fingerprint in both texts. Expected fingerprint density for ordinary text is approximately `2/(w+1)`; actual density depends on repeated hashes and text content. Hash matches are checked against the full normalized shingle to guard against a hash collision.

The inverted index is SQLite with foreign keys enabled and a B-tree index on fingerprint hash. Each entry retains source ID, token position, original character offsets, and the shingle. Re-indexing a source ID replaces its old rows. The database records the selected `k` and `w`; opening it with different parameters fails explicitly. Source title, URL, and license are retained for attribution.

Every matching fingerprint is expanded across adjacent identical normalized words and aligned query/source ranges are merged. Per-source overlap is distinct query-word positions covered by exact normalized matches divided by query word count. Overall overlap is the union of query-word positions covered by any source divided by query word count. Both are percentages, not probabilities, plagiarism decisions, or authorship labels. Use `exclude_source_ids` in the library or `--exclude-source` in the CLI when a query is also present in the index.

The corpus helper downloads page extracts through Wikipedia's MediaWiki API and records permanent revision links, page IDs, hashes, and the declared CC BY-SA 4.0 license in `corpus-manifest.json`. Wikipedia attribution is provided through the per-page revision URL; text is retained only in ignored local storage. The generated index is also local and rebuildable. See `docs/DATASETS.md` for reuse terms and data handling.

## Milestone 5 experiment protocols and execution

An experiment protocol records its research question, hypothesis, explicit classification rule, planned metrics, seed, version, conditions and declared transformations. It snapshots each selected document's ID, original SHA-256, extraction text hash, filename, declared provenance and research metadata, plus detector keys, database IDs, model revisions and score semantics. Once queued, this JSON protocol is immutable. Duplicating a run creates a new draft with the same snapshot.

The runner processes the Cartesian product of snapshot documents and detectors one pair at a time. Inference runs in a worker thread so API requests can still cancel the experiment. Every result, including a per-item failure with no score, is committed before advancing progress. Cancellation takes effect between pairs; an in-flight pair is allowed to finish. Successful pairs are retained during resume, while failed pairs are retried in place and their attempt count is recorded. A backend restart marks active snapshot-based runs partial and schedules work that was queued but had not begun. Legacy single-document inference rows are excluded from this recovery path.

The classification rule and metrics list are protocol declarations only. Milestone 5 does not convert scores to classes, compute binary metrics, apply perturbations, or produce aggregate conclusions. Those are later research and statistics work.

## Milestone 6: statistics

M6 accepts structured `m6.1` rules that freeze positive and negative declared provenance labels and each detector's score direction and threshold. Threshold metrics (accuracy, precision, recall, specificity, F1, FPR, FNR, Cohen's kappa, and confusion counts) are calculated only when every detector has an explicit threshold. AUROC and AUPRC use the frozen direction without converting scores into probabilities. Probability calibration and ECE are refused unless the stored detector semantics are `probability`; a percentage score is never treated as a probability.

The analysis endpoint reads the experiment's immutable document provenance and detector outputs. Numeric observations are the only observations included in estimates. Censored and missing outputs are separately counted and excluded; neither is converted to zero. Every result includes its n and class counts. The default 95% percentile bootstrap uses the frozen protocol seed and at least 2,000 resamples. Subgroup rows report n and mark cells below the configurable floor (30 by default) unreliable. Detector comparisons use common scored document IDs, decision agreement/kappa, Spearman, exact McNemar p, and paired document bootstrap AUROC differences when both classes are present.

The split leakage helper rejects author, source, or duplicate group identifiers that cross train/validation/test. M6 does not tune thresholds: separate grouped validation and protocol preregistration are required before any future threshold selection. Calibration bins use equal-width [0,1] bins. These descriptive intervals do not correct for multiple comparisons or selection after inspecting results.

## Milestone 7: manual Turnitin report import

MIA makes no Turnitin API calls and never submits documents. A researcher can import a report only after the institution authorizes the activity and its repository settings are understood. The importer requires a selected document UUID, explicit identity confirmation, and the submitted-file SHA-256 matching that document's stored original. The report's eligible word count must be within the researcher-declared tolerance of the extracted document word count; the comparison and tolerance are stored with the record.

The original report file (PDF, PNG, or JPEG; at most 20 MB) is stored unchanged under `storage/reports/<report UUID>/` with its SHA-256. Report reference, report timestamp, ingestion timestamp, detector version, and passage annotations are retained. Similarity and AI-writing fields preserve the raw display string and store a typed state (`value`, `censored_low`, or `not_displayed`). Only `value` has a numeric percentage. A censored marker such as `*` is kept verbatim, with an optional upper bound; it is never converted to zero. Imported rows appear with percentage semantics in the document and experiment result views.

The application does not independently parse or authenticate vendor report contents. Identity confirmation, source report review, eligibility tolerance, and score-state selection remain researcher responsibilities. Synthetic test fixtures verify validation and storage behavior; they are not Turnitin reports or research results.

## Milestone 8 report generation

`POST /api/experiments/{id}/reports` is available only for a completed experiment with an analyzable structured M6 protocol. It reads the frozen experiment snapshot and persisted result rows, invokes the same deterministic analysis calculation exposed by `/api/analysis/experiments/{id}`, and writes one Markdown report and one raw-observation CSV under `storage/reports/generated/`. SHA-256 digests, commit revision, and a compact analysis summary are persisted in the generated-report row. The API returns download links; the report index and downloads are available at `/api/reports` and `/api/reports/{id}/markdown` or `/api/reports/{id}/csv`.

Markdown includes the question and hypothesis, classification rule, snapshot and declared-provenance counts, detector model revisions and score semantics, metric estimates with bootstrap intervals and sample sizes, subgroup estimates with low-n flags, automatically populated limitations, and a reproducibility block. The CSV contains individual persisted outputs and errors without recomputing scores; manual Turnitin observations are included as raw imported observations, preserving their display string and typed censoring state. Small subgroup cells are marked unreliable and omit bootstrap intervals rather than suggesting precision from tiny samples. Regenerating the report recomputes analysis deterministically from the frozen seed and current committed analysis code; generated timestamps and report IDs differ.

The Analysis page receives `observations`, `roc_curve`, and `score_distribution` from the API along with the existing metrics, intervals, subgroups, and n. ROC points use the experiment's declared positive class and score direction. Score bins are calculated in the backend from observed stored scores. The frontend only plots these values and never recomputes metric estimates.
